What the evaluation covers

5 Playwright E2E spec flows (from TEST_STRATEGY.md §2.4)

18 regression scenarios (from TEST_STRATEGY.md §4.1)

Process

  1. For each of the 6 completed build branches, check out the branch into an isolated git worktree at /tmp/opencode/eval-func/<branch>.
  2. Boot the app the way the spec requires: docker compose --profile https up -d (preferred for fidelity — real Caddy TLS + rate limiting + /data volume), falling back to npm run dev + npx tsx src/scripts/seed.ts. Verify /api/health returns 200.
  3. If a branch is missing a Playwright spec file (common — only claude-5.2, claude-5.1, and vscode-5.2 ship any), write the canonical spec from TEST_STRATEGY.md into the worktree's tests/e2e/. This gives every build an equal functional test. Do not commit these specs.
  4. Run all 5 spec flows with the 18 regression scenarios as in-flow assertions. Run each flow 3× to surface flakiness (rate-limit 429s under Caddy are recorded as info, not failure).
  5. For each failing scenario, produce an effort estimate (S/M/L/XL: <15 / <60 / <240 / >240 min) and a targeted AI remediation prompt (≤300 chars) referencing the failing file/function and the spec section.
  6. Write docs/FUNCTIONAL_EVALUATION.md with the exact section layout the site parses, update site/assets/data.js with the new functional results, and commit both on main. The site redeploys automatically.
  7. Do not patch or commit changes to any build branch — preserve single one-shot-prompt fidelity.
