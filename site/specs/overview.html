Specification Documents

The complete specification fed to every coding agent in this one-shot-prompt experiment. All docs live in docs/ on main.

The one-shot prompt. Every build was generated by feeding this single instruction to each agent — “read and execute docs/BUILD_PROMPT.md to build this application” — with no follow-up turns, no clarification, and no patching. The agent was expected to read every spec doc in order, then produce the entire application.

Documents

Read order

The build prompt instructs agents to read the spec docs in this exact order before writing any code:

  1. docs/REQUIREMENTS.md — what to build
  2. docs/ARCHITECTURE.md — how it's structured
  3. docs/DESIGN.md — how each feature works
  4. docs/IMPLEMENTATION.md — how to write the code
  5. docs/API_REFERENCE.md — every endpoint
  6. docs/UI_SPECIFICATION.md — every page
  7. docs/OPERATIONS.md — deployment, backup, monitoring
  8. docs/TEST_STRATEGY.md — what tests to write

After reading, the agent confirms understanding of the 6 v2 simplifications (2 roles + canViewAll, no CSRF token, no session revocation, no account lockout, no in-app rate limiter, single-source profit, no auto $0 sales, app_config single-row, 6-table schema, withAuth wrapper, server components, no Kubernetes).
