About this evaluation

A controlled experiment in spec-driven, one-shot-prompt software generation across ten AI coding agents.

The experiment

Ten AI coding agents were given the same single instruction — “read and execute docs/BUILD_PROMPT.md to build this application” — with no follow-up turns, no clarification, and no patching. Each agent was expected to read the complete specification in docs/, then generate the entire Resell Inventory Manager v2 application from scratch.

Nine agents completed the build; one (build-ibm-bob) exhausted its usage quota mid-build and is excluded from scoring. The nine completed builds are evaluated across two dimensions:

  1. Static analysis — spec conformance, maintainability, vulnerabilities, complexity, and test signal. Source: docs/BUILD_EVALUATION.md.
  2. Functional (E2E) testing — Playwright end-to-end runs of the 5 spec flows and 18 regression scenarios against each running build, with per-failure effort estimates and remediation prompts. Source: docs/FUNCTIONAL_EVALUATION.md (populated by the eval prompt).

This site

A zero-build, framework-free static site. All evaluation data lives in site/assets/data.js, rendered via vanilla JavaScript. No Node, no Jekyll, no VitePress, no npm install required to view it.

Deployment is automatic via GitHub Actions: any push to main that touches site/** or docs/** uploads site/ as a Pages artifact. Enable Settings → Pages → Source = GitHub Actions once in the repo.

When the functional evaluation is run, the agent writes docs/FUNCTIONAL_EVALUATION.md and updates site/assets/data.js; the next push redeploys the site with the populated functional results page.

Reproducing

Reproducing the static analysis

The methodology is documented in Appendix A of docs/BUILD_EVALUATION.md: check out each branch into an isolated git worktree, run npm ci / lint / tsc --noEmit / vitest run, and inspect the source.

Reproducing the functional evaluation

Copy the eval prompt into any coding agent with access to this repo. The prompt is resumable and self-contained.

Reproducing a build

Check out any build-* branch and run npm ci && npm run dev, or docker compose --profile https up -d per docs/OPERATIONS.md.
