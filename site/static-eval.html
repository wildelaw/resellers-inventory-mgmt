§5 Vulnerabilities

All six implement validateOriginOrReferer for POST/PUT/DELETE/PATCH, returning 403 on missing/mismatched Origin/Referer. No raw SQL, no eval, no dangerouslySetInnerHTML anywhere. Key differences below.

  • build-claude-glm-5.2: most robust — configurable ORIGIN_EXEMPT_PREFIXES, rejects with 403 when no host established, explicit SameSite=strict, live JWT refresh of passwordChangedAt/role/canViewAll/isActive, withAuth also rejects deactivated accounts.
  • build-pi-glm-5.1: CRITICAL — jwt callback copies id/role/canViewAll but never copies passwordChangedAt. token.passwordChangedAt is always 0, so withAuth's check is always false → password changes do not invalidate existing JWTs. Directly violates AUTH-02/SEC-03. Severity: High.
  • SameSite cookie: only claude-5.2 and opencode-5.2 explicitly set sameSite:'strict' as the spec requires. The other four rely on NextAuth defaults (lax).

Appendix A — Raw verification

Methodology
  1. Worktrees. Each branch checked out into an isolated git worktree under /tmp/opencode/eval/<branch>.
  2. Static analysis. File censuses via find + wc. Type-escape and dangerous-pattern counts via grep -rn over src/ (tests excluded unless noted).
  3. Dynamic verification. Per worktree: npm ci --no-audit --no-fund, then lint, then npx tsc --noEmit, then npm test. All six installed cleanly under Node 24.15 / npm 11.12.
  4. No patching. Branches were not modified — broken lint or missing endpoints recorded as-is.
  5. No commits. Only this report was written; nothing committed. Worktrees under /tmp/opencode/eval/ are throwaway.
  6. build-ibm-bob excluded. Did not complete (agent exhausted Pro plan quota mid-build). Branch remains in repo for reference.
